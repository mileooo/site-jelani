# Российская инфраструктура JELANI

## Выбранный вариант

Для JELANI рекомендуется Yandex Cloud в регионе Россия:

- `Serverless Containers` — Node.js API, обработчики заказов, авторизации, Telegram и webhook ЮKassa;
- `Managed Service for PostgreSQL` — клиенты, адреса, заказы, статусы, бонусы и согласия;
- `Lockbox` — секретный ключ ЮKassa, токены Telegram, SMS и OAuth;
- `Cloud Logging` — технические журналы без записи лишних персональных данных;
- `Object Storage` и российский CDN — статические файлы сайта и изображения, если весь сайт переносится с Cloudflare;
- `Cloud DNS` — по желанию; домен `jjelani.ru` менять не требуется.

Yandex Cloud публикует сведения о соответствии ФЗ-152 и размещении инфраструктуры в России. Это помогает выполнить требования к инфраструктуре, но не освобождает ИП от собственных обязанностей оператора персональных данных.

Официальные материалы:

- https://yandex.cloud/ru/security/standards/152-fz
- https://yandex.cloud/ru/docs/serverless-containers/
- https://yandex.cloud/ru/docs/managed-postgresql/
- https://yandex.cloud/ru/docs/lockbox/

## Целевая схема

```text
Покупатель
    │ HTTPS
    ▼
jjelani.ru — российский CDN / Object Storage
    │ same-origin /api
    ▼
API Gateway или Load Balancer
    │
    ▼
Serverless Container — Node.js API
    ├── Managed PostgreSQL (приватная сеть)
    ├── Lockbox (секреты)
    ├── ЮKassa (платежи и чеки)
    ├── Telegram (кухня)
    └── SMS / OAuth-провайдеры
```

Cloudflare можно оставить только в роли DNS без проксирования трафика. Оранжевое облако Cloudflare для сайта и API следует отключить, чтобы запросы с именем, телефоном и адресом не проходили через зарубежный reverse proxy.

## План переноса

1. Создать организацию, платёжный аккаунт и отдельный каталог `jelani-production` в Yandex Cloud.
2. Создать приватную сеть, PostgreSQL и сервисный аккаунт с минимальными правами.
3. Перенести схему SQLite/D1 в PostgreSQL и заменить D1-адаптер в API.
4. Перенести существующие заказы и аккаунты по защищённому каналу, сверить количество строк и контрольные суммы.
5. Поместить секреты в Lockbox. `shopId` ЮKassa можно хранить как настройку; секретный ключ — только как секрет.
6. Развернуть контейнер, проверить тестовый платёж, чек, webhook, отмену и полный возврат.
7. Переключить DNS на российскую инфраструктуру и только после проверки установить `PERSONAL_DATA_LOCALIZED=true`.
8. Оставить старую систему в режиме чтения на короткий период, затем удалить персональные данные по утверждённому регламенту.

## Настройки ЮKassa для JELANI

```text
YOOKASSA_PAYMENT_METHODS=bank_card,sbp
YOOKASSA_RECEIPTS=true
YOOKASSA_VAT_CODE=1
YOOKASSA_PAYMENT_SUBJECT=commodity
PUBLIC_SITE_URL=https://jjelani.ru
```

Для ПСН выбран код `1` — «Без НДС». Блюда передаются в чек как товар, доставка 149 ₽ — отдельной услугой. Email покупателя обязателен, потому что «Чеки от ЮKassa» отправляют чек на электронную почту.

## Что нельзя присылать в чат или хранить в Git

- секретный ключ ЮKassa;
- токен Telegram-бота;
- пароль PostgreSQL;
- `ADMIN_API_TOKEN` и `AUTH_SECRET`;
- резервные копии с именами, телефонами, email и адресами клиентов.

Перед запуском нужно отдельно проверить уведомление Роскомнадзора, модель угроз, локальные документы оператора, договоры с обработчиками и фактический налоговый режим с юристом и бухгалтером.
